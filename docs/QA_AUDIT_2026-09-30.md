### Qualitative assessment

A fixed sample of four claims at 15/35/60/85% of each map, plus the final two synthesis candidates per map, was inspected. The proposition/stance separation handles negation well when the stance is read: an affirmative canonical proposition can correctly have a rejecting speaker. UI and evaluation must always carry that stance. Short quotes such as “those arguments either way” require surrounding-turn context; exact character matches alone are insufficient evidence of semantic fidelity.

The core taxonomy is adequate for the intended instrument: speech acts, independent propositions, attributed stances, confidence, strata, attack types, inferred convergence, and candidate synthesis. The main risks are inference and presentation discipline rather than a need for more entity types:

- There are only three explicit same-proposition disagreements against 78 cross-claim clashes. Identity/stance coverage needs an annotated evaluation. Do not relabel inferred clashes as demonstrated double cruxes.
- Crux ranking is a graph heuristic. It does not establish both participants' counterfactual dependence or enforce the ontology's single inferred-link limit. It can nominate the disputed proposition itself. Keep “Candidate” and expose each side's update conditions and dependency evidence.
- L4 validates references but has no independent semantic consistency/signability critic. For example, Ball–Kokotajlo `l4:036:hg0` proposes holding major international measures until triggers appear, although the cited participant calls for agreements. This is a proposed concession to test, not established shared ground. Existing crux cards also include speculative update conditions prefaced “Not stated directly”; the cockpit now labels these conditions for verification, but the analysis still needs quote-backed validation of each one.
- The existing inferred flag describes whether supporting commitments are inferred. A card with `reliesOnInferred: false` is still a model-proposed synthesis, not a participant-approved conclusion.
- Distinguish shared commitments, related-but-inferred convergence, and a new negotiated proposal. The UI now makes possible costs and attack semantics clearer, but human review remains essential.

## 6. Remaining issues and release blockers

1. **P0 — End-to-end audio fidelity and headroom.** Short live ASR cuts dropped words that whole-window transcription retained. Both combined audio runs are under the desired 2× preparation headroom. Measure contextual/overlapping live chunking before changing thresholds or models; preserve word timestamps and deduplicate overlaps. Then run actual capture → ASR → diarization → reviewed attribution → L1–L4 against held-out references.
2. **P0 — Attribution workload and hardware qualification.** Call/room gates remain insufficient and all lines held. Separate tracks have not passed a physical crossed-mic/crosstalk test. The channel fast path samples voices after logging; it is not a guarantee of zero unflagged swaps. Energy/time-overlap copy filtering can discard genuine simultaneous speech. Test that case explicitly before certifying separate-track ingestion.
3. **P1 — Analysis resume gaps.** `SessionEngine.finishedBefore` skips a previously logged L1 turn even if L2 never completed, and infers older completion from later closed turns. A reload/provider failure can leave analysis missing. Resume should continue the logged L1 proposal through its remaining review steps without generating different content under existing IDs. This audit did not redesign the analysis checkpoint protocol.
4. **P1 — Synthesis and root-crux validation.** Reference validation is necessary but insufficient. Complete independent signability/consistency evaluation and participant reviews; enforce the ontology's dependency requirements before claiming roots of disagreement are established.
5. **P1 — Human gold and quality-gate mismatch.** Adjudicated faithfulness, hedge/scope, relation, crux and synthesis gates remain unproven. The attribution lab's 2% ceiling is weaker than QUALITY.md's 0.5% wrong-auto gate and zero unflagged live swaps. Small or surrogate samples are not passes.
6. **P2 — Audience module wiring.** `audienceView` maps older `question` insight kinds but not current `prompt`/`shared` kinds. This is a functional omission, not a raw-data leak. Resolve it together with feature-level quality gating; audience channels must still receive only released, allowed audienceView output.
7. **P2 — Historical artifacts and documentation.** Apply a deliberate correction to the one known old rhetorical-strength violation; reconcile runtime model and stale plan/handoff documentation. Recheck all old cards after any extraction/merge change rather than assuming this local fix rewrites them.

R1 remains blocked on the documented held-out quality gates, a 90-minute 1× soak, the actual room/input hardware test with zero unflagged swaps, and a facilitator rehearsal. This audit's successful unit/browser checks do not substitute for those gates.

## Live-test follow-up: fragmented transcript evidence

A host test exposed a separate L1 quote-location defect. The extractor sees a complete turn made by joining ASR chunks with one space, but the mapper previously searched each chunk independently. A perfectly exact quote spanning two chunks therefore lost its ADU and stance. Under the earlier approval behavior, this could leave an approved proposition without a speaker connection; the September 30 release already prevents that orphan approval, but the quote loss itself also needed fixing.

L1 now locates exact quotes in the same joined text the model receives and splits the result into source spans with independently valid character offsets. It preserves every source character, rejects paraphrases/case changes/skipped words, and refuses cross-speaker spans. Single-utterance matching used elsewhere remains unchanged. Failed quote diagnostics now retain the unmatched model quote so future failures can distinguish chunk boundaries from altered wording. No prompt, model, effort or attribution threshold changed.

Four regression tests cover a hedged claim across three chunks through approval, exact two-chunk matching, invalid/altered quotes, and cross-speaker rejection. These scripted cases verify the mapping mechanism; they do not establish model extraction recall on new live audio.

The same test also confirmed that an unconfirmed short continuation remains outside analysis. Room/call attribution is intentionally capped at 0.84 while its quality gate is insufficient, below the 0.85 acceptance threshold. A raw voice score of 1 represents matching cluster time, not a calibrated probability of correct identity. A timeout that accepts an unattended line would relax that gate; no such change was made. Consider a reviewed, grouped-confirmation interface and a pre-end review step independently of any auto-accept threshold change.
